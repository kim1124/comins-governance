# Comins 커밋 메시지 작성 원칙

이 문서는 Comins 공통 Contract의 커밋 작성 규칙을 구체화합니다.
커밋을 준비할 때 적용하며, 커밋이나 원격 작업 권한을 부여하지 않습니다.
기준 자료: [How to Write a Git Commit Message](https://cbea.ms/git-commit).

## 제목과 본문

- 제목과 본문은 한국어로 작성합니다. 코드·API 식별자, 명령, URL,
  이슈 번호와 Git trailer는 필요한 원문 표기를 유지합니다.
- 제목은 변경 동작 중심으로 간결하게 작성하고, 50자 이내를 권장합니다.
  원문의 영문 명령형은 한국어에서 `추가`, `수정`, `제거` 등의 동작
  중심 요약으로 적용합니다. `수정했습니다` 같은 완료 보고는 피합니다.
- 영어 첫 글자 대문자 규칙은 한국어 제목에 적용하지 않습니다.
- 제목 끝에는 마침표를 붙이지 않습니다.
- 제목과 본문 사이에는 빈 줄을 둡니다.
- 본문은 72자 내외로 줄바꿈합니다. 길이는 권장 기준이며,
  한글 표시 폭과 코드·URL의 가독성을 고려합니다.
- 본문에는 무엇을 변경했고 왜 필요한지 설명합니다. 기존 문제,
  선택 이유, 필요한 영향·부작용을 기록하고 구현 절차를 반복하지 않습니다.

## 필요한 설명만 기록

- 단순 오탈자처럼 변경 의도가 명확하면 제목만 작성해도 됩니다.
- 제목으로 요약하기 어렵다면 독립된 변경을 한 커밋에 묶었는지 확인합니다.
- 관련 이슈는 실제 연결이 있을 때 본문 하단에 기재합니다.
- 저장소의 기존 scope·trailer 표기와 필요한 자동화 형식은 유지하되,
  설명 문장은 한국어로 작성합니다.

## 예시

```text
README 문구를 줄여 지침 예산 초과 해결

브랜드 링크 추가로 README가 기존 1,800바이트 제한을 초과했다.
모듈 적용과 감사 안내의 중복 표현을 줄여 제한 이내로 정리한다.

브랜드 요소와 필요한 안내는 유지하고 제한값은 변경하지 않는다.
```
